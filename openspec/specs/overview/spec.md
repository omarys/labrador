## Purpose

A command-line and terminal UI application for searching, discovering, and downloading manga and
comic chapters across multiple online providers. It packages downloaded pages into CBZ archives
enriched with ComicInfo.xml metadata and offers interactive educational lessons on archive packaging
and CLI contracts.

## Requirements

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:
- Use per-provider concurrency throttling and rate-limit backoff in Downloader to manage request throughput across diverse webcomic platforms
- Enforce strict URLPolicy validation on all provider-supplied URLs to mitigate request tampering and SSRF risks
- Package chapters into standardized CBZ archives bundled with ComicInfo.xml metadata rather than leaving raw image folders
- Support dual presentation interfaces (headless CLI and Bubbletea-like Elm-architecture TUI with mouse support) sharing a common provider and downloader core
- Decouple webcomic providers through a thread-safe registry pattern with support for conditional build-tag private provider registration

#### Scenario: CapabilitiesProvided
- **GIVEN** the system is operational
- **WHEN** a user interacts with the system
- **THEN** the system provides the documented capabilities

### Requirement: DataFlow

The system SHALL process data through defined layers:

#### Scenario: StandardDataFlow
- **GIVEN** an incoming request
- **WHEN** the request is processed
- **THEN** data flows through: User commands/interactions originate in the CLI (e.g., runFetch, runChapters) or TUI (Update/View) → dispatched via LabradorApplication/App → Provider registry invokes specific provider adapter (e.g., MangaDex, Webtoons) to fetch series metadata and chapter page URLs → validated through URLPolicy → Downloader fetches chapter image assets with provider concurrency throttling → ArchiveService writes images and generated ComicInfo.xml into atomic CBZ archive files on disk; queue state is cached via QueuePersistenceService.

## Technical Notes

- **Architecture Style**: Layered architecture: Presentation layers (CLI and Elm-architecture TUI) delegate to application orchestration and core services (Downloader, ArchiveService, LibraryService), which interact with domain models, HTTP client policies, and external provider adapter implementations.
- **Security Model**: Strict outbound request validation via URLPolicy, which validates provider-supplied URLs to enforce constraints including permitted schemes, hostnames, allowed ports, and blocking credentials or URL fragments. No end-user authentication or authorization is present in the codebase evidence, as this is a local client application.
- **External Integrations**: MangaDex API, MangaKatana, Manganato, Manganelo, MangaPill, ReadComicsOnline, Webtoons, WeebCentral, Local Filesystem (CBZ archives and disk queue cache)
